## Overview

Snake is one of the most widely played video games in history, achieving mass distribution through its inclusion on Nokia mobile phones in the late 1990s. The rules are elemental: a snake moves continuously in one direction, the player changes that direction, and eating food pellets causes the snake to grow longer. The game ends when the snake collides with itself or, depending on the variant, with the walls. This simplicity maps perfectly to FPGA hardware — the entire game state fits in a circular buffer and a bitmap grid, with no frame buffer or CPU required.

Videomancer's implementation renders the snake on a 48x27 cell grid where each cell occupies 40x40 pixels at 1080p. Direction is controlled by two potentiometers acting as a dual-axis joystick: Knob 2 sets the X-axis and Knob 3 sets the Y-axis. The dominant axis wins, and 180-degree reversals are prevented so the snake cannot immediately double back on itself. Food pellets appear at LFSR-generated grid positions. Each food eaten increments the score and extends the snake by one cell. On death, the game pauses briefly then auto-resets.

At full mix, Snake renders as a clean game overlay on black. Reducing the mix fader blends the game with the input video, creating compositions where the serpent weaves through live imagery. The wrap/solid wall toggle changes the game topology — wrap mode makes the grid toroidal (the snake exits one edge and re-enters the opposite), while solid mode kills the snake on boundary contact.

## Background

### Nokia and the Mobile Snake Explosion

The original Snake concept dates to the 1976 arcade game Blockade, but it was Taneli Armanto's 1997 implementation for Nokia 6110 that made it a global phenomenon. The Nokia version ran on a monochrome 84x48 pixel LCD — remarkably close to Videomancer's 48x27 cell grid. The game's popularity demonstrated that compelling gameplay requires neither color nor high resolution, only clear rules and responsive controls. Videomancer's FPGA implementation follows the same minimalist philosophy, using a 1-bit grid bitmap and a circular position buffer instead of a frame buffer.

### Grid-Based Movement

Unlike games with continuous positioning, Snake operates on a discrete grid. The snake head occupies exactly one cell and moves to an adjacent cell at each tick. This quantized movement simplifies collision detection to a single bit lookup: if the target cell's grid bit is set, the snake has collided with itself. Videomancer implements this with a std_logic_vector per row — 48 bits per row times 27 rows — and a circular buffer of (x, y) coordinates tracking the last 128 body segment positions. The tail is erased by clearing the grid bit at the oldest buffer position each tick.

### Dual-Pot Direction Control

Traditional Snake uses four discrete buttons (up/down/left/right). Videomancer maps direction to two analog potentiometers, creating a joystick-like interface. Each pot's value is compared to a center dead zone (256-768). Values below 256 or above 768 register as directional input; within the dead zone, the snake maintains its current heading. The axis with the larger deflection from center wins, providing unambiguous direction selection even when both pots are off-center. A reversal guard prevents the snake from turning 180 degrees, which would cause instant self-collision.

### LFSR Food Placement

Food position is generated by a 16-bit linear feedback shift register (LFSR) using the polynomial x^16 + x^14 + x^13 + x^11 + 1. The LFSR advances once per vsync, and when food is consumed, the current LFSR state is mapped to grid coordinates via modular arithmetic (mod 48 for X, mod 27 for Y). This produces a pseudo-random but deterministic sequence — the same seed always generates the same food positions, enabling repeatable gameplay patterns useful for video art.

### Toroidal vs Bounded Topologies

The Walls toggle switches between two fundamentally different game topologies. In wrap mode, the grid is toroidal: the snake leaving the right edge appears on the left, and leaving the bottom appears at the top. This creates an unbounded playing field where the only threat is self-collision. In solid mode, the grid boundaries are lethal, adding four walls of danger and significantly increasing difficulty. Both modes use the same rendering pipeline — only the head position update logic differs.

## Signal Flow

```
Synthesis Engine
|
+-- Parameter Mapping ------------------------------------------------
|   +- registers_in(0)  -> Speed (move interval)
|   +- registers_in(1)  -> Dir X (joystick horizontal)
|   +- registers_in(2)  -> Dir Y (joystick vertical)
|   +- registers_in(3)  -> Start Length
|   +- registers_in(4)  -> Body Hue (chroma offset)
|   +- registers_in(5)  -> Brightness (foreground Y level)
|   +- registers_in(6)  -> Toggles (walls, grid, score, color, bypass)
|   +- registers_in(7)  -> Mix
|
+-- Game Logic (per vsync) -------------------------------------------
|   +- 1. Direction Decode   (dual-pot dominant axis, reversal guard)
|   +- 2. Move Timer         (frame counter vs speed interval)
|   +- 3. Head Position      (add direction, wall check/wrap)
|   +- 4. Self-Collision     (grid bitmap lookup at new head)
|   +- 5. Tail Erase         (clear oldest circular buffer entry)
|   +- 6. Food Check         (position match, grow + score)
|   +- 7. Food Spawn         (LFSR mod grid dimensions)
|
+-- Rasterizer (per pixel) -------------------------------------------
|   +- 8. Grid Cell Lookup   (h_count/40, v_count/40)
|   +- 9. Snake Hit Test     (grid bitmap)
|   +- 10. Food Hit Test     (position match)
|   +- 11. Grid Line Test    (cell_px < 2 or cell_py < 2)
|   +- 12. Border Hit Test   (4-pixel edges)
|   +- 13. Score Digit Lookup (5x7 font ROM at 4x scale)
|   +- 14. Color Mux         (priority: snake > food > score > border > grid > bg)
|
+-- Output Stage ----------------------------------------------------
|   +- 15. Interpolator Mix  (3x interpolator_u wet/dry)
|
+-- Sync Pipeline ---------------------------------------------------
|   +- 6-clock shift register (hsync, vsync, avid, field)
|
+-- Bypass ----------------------------------------------------------
    +- Select processed or input signal
```

The game logic executes entirely during the vsync blanking interval, updating head position, tail erasure, collision detection, and food spawning in a single deterministic pass. The rasterizer operates during active video, reading the grid bitmap and food coordinates to determine which game element (if any) occupies the current pixel. The direction decode uses a dead-zone threshold to filter out noise from the analog potentiometers, ensuring that only deliberate deflections beyond the 256/768 thresholds register as directional input.

The circular buffer stores up to 128 body segment positions, with a head pointer that advances modulo 128 on each move. The tail is identified by subtracting the current snake length from the head pointer. This approach allows O(1) grow and shrink operations without scanning the entire body list.

## Parameter Reference

<img src={snake_control_panel} alt="Videomancer front panel with Snake loaded"/>
*Videomancer's front panel with Snake active. Knobs 1–6 (top two rows of left cluster), Toggle switches 7–11 (bottom row of left cluster), Fader 12 (right side).*

### Rotary Potentiometers (Knobs 1–6)

#### Knob 1 — Speed
| Property | Value |
|----------|-------|
| Range | 0% – 100% |
| Default | 38% |
| Suffix | % |

Speed controls the interval between snake movement ticks. At low values, the snake moves slowly with many frames between steps, giving the player time to plan turns. At high values, the snake races across the grid with nearly one-step-per-frame timing. The speed pot maps inversely to the move interval: higher pot values produce shorter intervals and faster movement. Finding the right speed depends on the player's familiarity with the dual-pot direction interface — beginners should start slow.

---

#### Knob 2 — Dir X
| Property | Value |
|----------|-------|
| Range | 0% – 100% |
| Default | 75% |
| Suffix | % |

Dir X provides the horizontal component of the direction joystick. When turned far left (below the dead zone threshold), the snake turns to face left. When turned far right (above the threshold), it turns right. Within the center dead zone, the X axis is ignored and the current heading persists. This pot works in concert with Dir Y — the axis with the larger deflection from center determines the new direction.

---

#### Knob 3 — Dir Y
| Property | Value |
|----------|-------|
| Range | 0% – 100% |
| Default | 50% |
| Suffix | % |

Dir Y provides the vertical component of the direction joystick. When turned far left (below threshold), the snake turns upward. When turned far right (above threshold), it turns downward. Like Dir X, the center dead zone prevents accidental direction changes. The dominant-axis-wins logic ensures that diagonal pot positions always resolve to a single cardinal direction, never a diagonal.

---

#### Knob 4 — Start Len
| Property | Value |
|----------|-------|
| Range | 0% – 100% |
| Default | 25% |
| Suffix | % |

Start Len sets the initial length of the snake when the game begins or resets after death. Longer starting lengths create a more challenging opening because the snake already occupies several cells, reducing the available safe space. Short starting lengths give the player maximum room to maneuver. The length also determines how many body segments must be tracked in the circular buffer from the start.

---

#### Knob 5 — Body Hue
| Property | Value |
|----------|-------|
| Range | 0% – 100% |
| Default | 50% |
| Suffix | % |

Body Hue shifts the chroma values applied to the snake body and food pellet when Color mode is set to Hue. Sweeping this knob rotates through the YUV color wheel, allowing the snake to appear in any hue from red through green through blue and back. In Mono mode, this knob has no visible effect — the snake renders as achromatic white at the current brightness level.

---

#### Knob 6 — Bright
| Property | Value |
|----------|-------|
| Range | 0% – 100% |
| Default | 75% |
| Suffix | % |

Bright controls the luminance (Y channel) of all foreground game elements — snake body, food pellet, score digits, and grid lines (which render at 1/16th of the brightness value). Higher values produce a vivid, high-contrast game against the black background. Lower values create a dim, ghostly snake that blends more subtly when mixed with input video.

---

### Toggle Switches (Switches 7–11)

| Switch | Off | On |
|--------|-----|-----|
| **7 — Walls** | Wrap | Solid |
| **8 — Grid** | Off | On |
| **9 — Score** | Off | On |
| **10 — Color** | Mono | Hue |
| **11 — Bypass** | Off | On |

The five toggles partition into gameplay (Walls), display options (Grid, Score, Color), and signal routing (Bypass). Walls directly affects game difficulty by switching between toroidal and bounded topologies. Grid and Score are independent display features that can be enabled or disabled without affecting gameplay. Color switches between monochrome and hue-tinted rendering. Bypass routes the input signal directly to the output, hiding the game overlay while the simulation continues running internally.

---

### Linear Potentiometer (Fader 12)

#### Fader 12 — Mix
| Property | Value |
|----------|-------|
| Range | 0.0% – 100.0% |
| Default | 100.0% |
| Suffix | % |

Mix controls the wet/dry blend between the game overlay and the input video. At full mix, only the Snake game is visible on a black background. Reducing mix fades in the input video behind the game elements, creating a transparent overlay effect. At zero mix, the game is completely hidden and only the input signal passes through. The mix engages the three interpolator_u instances for Y, U, and V channels independently.

## Guided Exercises

These exercises explore Snake's dual-pot direction system, the contrast between wrap and solid wall modes, and the use of mix blending for video overlay compositions.

### Exercise 1: First Hunt

<img src={snake_exercise1_result} alt="First Hunt result"/>
*First Hunt — simulated result across source images.*
**Objective**: Play a complete game of Snake using the dual-pot direction interface to eat five food pellets.

1. Set Speed to about 25% for a comfortable pace.
2. Set Dir X and Dir Y both to center (50%) — the snake maintains its initial rightward heading.
3. Set Start Len to minimum for maximum maneuvering room.
4. Turn Walls to Wrap for forgiving edge behavior.
5. Enable Score to track food eaten.
6. Turn Dir X fully right to keep moving right toward the first food pellet.
7. When the food is above or below the snake, turn Dir Y to steer up or down.
8. Practice alternating Dir X and Dir Y to navigate the grid.

**Key concepts**: Dominant axis selection, dead zone filtering, food LFSR placement, score incrementing

## Tips

- **Center the pots to hold course**: Keeping both Dir pots in the center dead zone maintains the current heading, letting the snake auto-pilot in a straight line until you deliberately steer.
- **One axis at a time**: Move only one pot at a time for clean direction changes. Deflecting both pots simultaneously relies on the dominant-axis logic, which can produce unexpected turns.
- **Wrap mode is your friend**: Start with Wrap mode to learn the controls without the pressure of wall death. Switch to Solid once you're comfortable with the dual-pot interface.
- **Watch the grid lines**: Enable Grid to see exactly where cell boundaries are — this helps time turns to avoid self-collision by one cell.
- **Speed is the difficulty knob**: Low speed gives time to plan; high speed demands reflexive control. Scale speed as you gain proficiency.
- **Mix for video art**: Reduce Mix to blend the snake game over live video input. The snake body becomes a moving, growing graphic overlay.
- **Bypass preserves state**: Toggling Bypass hides the game without pausing it. The snake continues playing invisibly and may die or eat food while hidden.

## Glossary

| Term | Definition |
|------|------------|
| **BCD** | Binary-Coded Decimal; each decimal digit is stored in 4 bits, used for the two-digit score display. |
| **Cell** | One 40x40 pixel region within the 48x27 grid, the fundamental unit of snake movement and collision. |
| **Circular Buffer** | A fixed-size array with a pointer that wraps from the last element back to the first, used here to store the last 128 snake body segment positions. |
| **Dead Zone** | The range of pot values (256-768) within which direction input is ignored, preventing accidental turns from slight pot drift. |
| **Dominant Axis** | The direction input axis (X or Y) with the larger deflection from center, which wins when both axes are deflected simultaneously. |
| **Grid Bitmap** | A 48x27 array of single bits where each set bit indicates a cell occupied by the snake body, enabling O(1) collision detection. |
| **LFSR** | Linear Feedback Shift Register; a shift register with XOR feedback taps that generates a pseudo-random bit sequence used for food placement. |
| **Reversal Guard** | Logic that prevents the snake from reversing 180 degrees, which would cause instant self-collision on the next move tick. |
| **Toroidal Grid** | A grid topology where the top edge connects to the bottom and the left edge connects to the right, used in Wrap mode. |
| **Vsync** | Vertical synchronization pulse marking the start of a new video frame, used as the game tick clock. |
| **YUV** | A color encoding separating luminance (Y) from chrominance (U, V), used throughout the Videomancer video pipeline. |
