## Overview

Simon is the classic electronic memory game, first manufactured by Milton Bradley in 1978. The device presents a sequence of colored light flashes, and the player must reproduce the sequence from memory. Each successful round adds one more step to the sequence, testing the limits of short-term recall. Videomancer's implementation renders four colored quadrants filling the screen in a two-by-two grid, separated by a narrow gap. The game logic runs entirely in FPGA fabric — no CPU, no frame buffer, just registers, an LFSR, and a 128-bit sequence store.

Gameplay is controlled through a unique analog interface: Knob 3 (Select) maps to one of four quadrants based on pot position, and Toggle 7 (Confirm) acts as the submit button. The game cycles through playback, input, success, and fail states. During playback, each quadrant flashes in turn at a tempo set by Knob 1. The player then selects each quadrant in order using the Select knob and confirms each choice. A correct sequence advances the score and adds a new LFSR-generated step; a wrong answer triggers a fail flash and resets to the beginning.

At full mix, Simon renders as a bold four-color pattern on black. Reducing the mix fader blends the quadrant display with input video, creating a live memory game overlay. The Border toggle adds a decorative frame around the quadrant grid, and the Score toggle displays the current level as a two-digit number centered on the gap between quadrants.

## Background

### The Original Simon

Ralph Baer and Howard Morrison invented Simon in 1978, inspired by Atari's Touch Me arcade game. The physical Simon device used four large translucent buttons (red, blue, green, yellow) arranged in a circle, each with its own tone. The genius of Simon was its accessibility — the rules could be understood in seconds, but mastering the game required genuine cognitive effort. The sequence length increased with each round, and the tempo accelerated, taxing both memory and reaction time. Videomancer's implementation captures this escalating difficulty by adding LFSR-generated steps after each successful reproduction.

### Memory Span and the Magical Number Seven

George Miller's 1956 paper "The Magical Number Seven, Plus or Minus Two" established that human short-term memory can hold approximately 7 items. Simon's design exploits this limit directly — players typically fail between sequences of 5 and 9 elements, right at the boundary of working memory capacity. Videomancer's implementation supports up to 64 steps in the sequence (128 bits / 2 bits per step), far exceeding human memory capacity and ensuring the game always wins eventually.

### LFSR Sequence Generation

The sequence is generated by a 16-bit linear feedback shift register using the polynomial x^16 + x^14 + x^13 + x^11 + 1. Each LFSR advance produces 2 bits, selecting one of four quadrants (0-3). The seed is derived from Knob 4 (Seed), so different seed positions generate entirely different game sequences. This makes the LFSR seed pot a difficulty/variety control — performers can practice specific sequences by returning to the same seed position, or explore new challenges by sweeping to a different value.

### Quadrant Rendering

The four quadrants are rendered by dividing the screen at the horizontal and vertical midpoints (960 and 540 pixels). Each quadrant receives a base brightness determined by its flash state — lit quadrants display at full brightness, unlit quadrants at approximately 1/8th brightness. The gap between quadrants (20 pixels) and optional border (40 pixels) provide visual separation. Color hue rotates in 90-degree steps per quadrant when Color mode is active, creating the classic red/green/blue/yellow arrangement offset by the Quad Hue knob.

### State Machine Architecture

The game uses a 3-bit state register implementing six states: IDLE, PLAYBACK, PAUSE, INPUT, SUCCESS, and FAIL. The state machine advances on vsync edges, making each frame a single game tick. During PLAYBACK, the current sequence step flashes for a duration set by Knob 2 (Flash) followed by a pause set by Knob 1 (Tempo). During INPUT, edge detection on the Confirm toggle registers player selections. SUCCESS waits 30 frames before adding a new step and returning to PLAYBACK. FAIL flashes all quadrants before resetting.

## Signal Flow

```
Synthesis Engine
|
+-- Parameter Mapping ------------------------------------------------
|   +- registers_in(0)  -> Tempo (pause duration between flashes)
|   +- registers_in(1)  -> Flash Duration (length of quadrant lighting)
|   +- registers_in(2)  -> Select (quadrant selection, 2 MSBs = quad 0-3)
|   +- registers_in(3)  -> Seed (LFSR initial value)
|   +- registers_in(4)  -> Quad Hue (chroma offset)
|   +- registers_in(5)  -> Brightness (foreground Y level)
|   +- registers_in(6)  -> Toggles (confirm, border, score, color, bypass)
|   +- registers_in(7)  -> Mix
|
+-- Game Logic (per vsync) -------------------------------------------
|   +- 1. State Machine   (IDLE → PLAYBACK → INPUT → SUCCESS/FAIL)
|   +- 2. LFSR Clock      (advance on seed load and step generation)
|   +- 3. Sequence Store   (128-bit register, 2 bits per step, max 64)
|   +- 4. Playback Index   (flash current step in sequence)
|   +- 5. Input Match      (compare selected quadrant to expected step)
|   +- 6. Confirm Edge     (rising edge detection on toggle 7)
|   +- 7. Score Update     (BCD increment on SUCCESS)
|
+-- Rasterizer (per pixel) -------------------------------------------
|   +- 8. Quadrant Decode  (h < 960, v < 540 → quad 0/1/2/3)
|   +- 9. Gap Detect       (h within HALF_W ± GAP/2 or v within HALF_H ± GAP/2)
|   +- 10. Border Detect   (h < BORDER or h > W-BORDER etc.)
|   +- 11. Flash State     (is current quad == flash_quad and flash_on?)
|   +- 12. Score Digits    (5x7 font at 6x scale, centered on gap)
|   +- 13. Color Mux       (quad brightness × flash state + hue offset)
|
+-- Output Stage ----------------------------------------------------
|   +- 14. Interpolator Mix  (3x interpolator_u wet/dry)
|
+-- Sync Pipeline ---------------------------------------------------
|   +- 6-clock shift register (hsync, vsync, avid, field)
|
+-- Bypass ----------------------------------------------------------
    +- Select processed or input signal
```

The game logic executes entirely during the vsync blanking interval, advancing the state machine one step per frame. During PLAYBACK, the frame counter alternates between the flash-on and pause-off phases, progressing through each sequence step before transitioning to INPUT. The confirm edge detector compares the current and previous frame's toggle state, registering a rising edge only when the toggle transitions from low to high. This prevents repeated inputs from holding the toggle.

The quadrant identification is a simple pair of comparisons: pixel X versus the horizontal midpoint and pixel Y versus the vertical midpoint yield a 2-bit quadrant ID. When the flash is active and the current quadrant ID matches the flash quadrant register, that quadrant renders at full brightness. Unlit quadrants render at diminished brightness (approximately bright/8), providing visual context for the quadrant layout even when no sequence is playing.

## Parameter Reference

<img src={simon_control_panel} alt="Videomancer front panel with Simon loaded"/>
*Videomancer's front panel with Simon active. Knobs 1–6 (top two rows of left cluster), Toggle switches 7–11 (bottom row of left cluster), Fader 12 (right side).*

### Rotary Potentiometers (Knobs 1–6)

#### Knob 1 — Tempo
| Property | Value |
|----------|-------|
| Range | 0% – 100% |
| Default | 50% |
| Suffix | % |

Tempo controls the pause duration between sequence flashes during playback. At low values, the pauses are very short, making the sequence fly by quickly and challenging memory recall. At high values, the pauses are long and leisurely, giving the player more time to register each quadrant. The base pause duration is 10 frames plus a fraction of the pot value, so even minimum settings provide a visible separation between flashes.

---

#### Knob 2 — Flash
| Property | Value |
|----------|-------|
| Range | 0% – 100% |
| Default | 50% |
| Suffix | % |

Flash controls how long each quadrant stays illuminated during sequence playback. Short flash durations create brief blinks that are harder to track, while long durations make each step obvious and easy to memorize. The base flash duration is 15 frames plus a fraction of the pot value. For performance use, shorter flashes create a more dynamic visual pattern; for gameplay, longer flashes are more accessible.

---

#### Knob 3 — Select
| Property | Value |
|----------|-------|
| Range | 0 – 3 |
| Default | 0 |

Select maps to one of four quadrants based on the two most significant bits of the pot value. The pot range is divided into four equal zones: 0-255 selects quadrant 0 (top-left), 256-511 selects quadrant 1 (top-right), 512-767 selects quadrant 2 (bottom-left), and 768-1023 selects quadrant 3 (bottom-right). The player turns this knob to choose a quadrant, then presses Confirm to submit the selection.

---

#### Knob 4 — Seed
| Property | Value |
|----------|-------|
| Range | 0% – 100% |
| Default | 50% |
| Suffix | % |

Seed sets the initial value of the 16-bit LFSR that generates the game sequence. Different seed values produce entirely different sequences of quadrant flashes. This allows performers to practice a known sequence by returning to the same seed position, or to generate new challenges by sweeping to a different value. The seed is loaded when the game transitions from IDLE to PLAYBACK.

---

#### Knob 5 — Quad Hue
| Property | Value |
|----------|-------|
| Range | 0% – 100% |
| Default | 50% |
| Suffix | % |

Quad Hue shifts the base chroma offset applied to the four quadrants when Color mode is active. Each quadrant receives an additional 90-degree hue rotation, so the four quadrants always display four distinct hues. Sweeping Quad Hue rotates the entire color wheel, cycling through warm, cool, and mixed palettes. In Mono mode, this knob has no visible effect — all quadrants render as achromatic luminance.

---

#### Knob 6 — Bright
| Property | Value |
|----------|-------|
| Range | 0% – 100% |
| Default | 75% |
| Suffix | % |

Bright controls the luminance (Y channel) of the lit quadrant state. Unlit quadrants are rendered at approximately 1/8th of this value, maintaining a dim background presence. Higher values create bold, vivid quadrant flashes; lower values produce subtle, ghostly pulses. The border and score digits also reference this brightness, with border at approximately 1/4 and score at 3/4 of the full value.

---

### Toggle Switches (Switches 7–11)

| Switch | Off | On |
|--------|-----|-----|
| **7 — Confirm** | Off | On |
| **8 — Border** | Off | On |
| **9 — Score** | Off | On |
| **10 — Color** | Mono | Hue |
| **11 — Bypass** | Off | On |

The five toggles divide into gameplay interaction (Confirm), display options (Border, Score, Color), and signal routing (Bypass). Confirm is unique among the toggles because it functions as a momentary action trigger rather than a persistent mode switch — the game detects its rising edge to register a player selection. Border, Score, and Color are purely visual and do not affect game state. Bypass routes the input signal past the game overlay.

---

### Linear Potentiometer (Fader 12)

#### Fader 12 — Mix
| Property | Value |
|----------|-------|
| Range | 0.0% – 100.0% |
| Default | 100.0% |
| Suffix | % |

Mix controls the wet/dry blend between the game overlay and the input video. At full mix, only the Simon quadrant display is visible. Reducing mix fades in the input video behind the game elements, creating a memory game overlay on live video. At zero mix, the game is invisible and only the input signal passes through. The mix engages three interpolator_u instances for Y, U, and V channels independently.

## Guided Exercises

These exercises explore Simon's sequence playback mechanics, the quadrant selection interface, and creative overlay compositions with input video.

### Exercise 1: Watch and Learn

<img src={simon_exercise1_result} alt="Watch and Learn result"/>
*Watch and Learn — simulated result across source images.*
**Objective**: Observe a full playback sequence and understand the flash and pause timing controls.

1. Set Tempo to about 50% for comfortable pause duration between flashes.
2. Set Flash to about 60% for clearly visible quadrant lighting.
3. Leave Select and Confirm at their defaults — just observe, don't input.
4. Enable Score to see the current level counter.
5. Enable Color for the four-color quadrant display.
6. Watch the first sequence play: one quadrant flashes.
7. The game transitions to INPUT state. Do not confirm yet.
8. Adjust Tempo and Flash to see how they change the playback rhythm.

**Key concepts**: Playback state, flash duration, pause interval, score display, state transitions

---

### Exercise 2: Play a Round

<img src={simon_exercise2_result} alt="Play a Round result"/>
*Play a Round — simulated result across source images.*
**Objective**: Successfully reproduce a sequence of 3+ steps using the Select knob and Confirm toggle.

1. Set Tempo to about 50% and Flash to about 60% for clear playback.
2. Set Seed to a specific position (e.g., ~25%) to get a reproducible sequence.
3. Watch the first playback sequence carefully — note which quadrant flashes.
4. When the game enters INPUT mode, turn Select to match the first quadrant.
5. Toggle Confirm on then off to submit your selection.
6. If correct, the selected quadrant flashes briefly as confirmation.
7. Repeat for each step in the sequence.
8. On SUCCESS, the score increments and the next round adds one more step.

**Key concepts**: Select-to-quadrant mapping, confirm edge detection, input validation, sequence growth, BCD scoring

### Exercise 3: Memory Game Video Overlay

<img src={simon_exercise3_result} alt="Memory Game Video Overlay result"/>
*Memory Game Video Overlay — simulated result across source images.*
**Objective**: Blend the Simon game at partial mix over live video input for a performance overlay composition.

1. Set Mix to about 55% to blend game and input video.
2. Set Bright to about 95% for vivid quadrant flashes visible through the mix.
3. Enable Color and sweep Quad Hue to find a palette that complements your input video.
4. Set Tempo fast (~25%) for rapid playback animation — the sequence becomes a visual pattern.
5. Disable Border for edge-to-edge quadrant rendering.
6. Enable Score for a persistent level counter overlay.

**Key concepts**: Partial mix blending, hue complementarity, rapid playback as visual pattern, overlay composition

## Tips

- **Watch the whole sequence**: During playback, focus on memorizing the order of all quadrant flashes. Trying to input before the sequence finishes is not possible — the game enforces playback completion before accepting input.
- **Use landmarks for Select**: The four quadrant zones on the Select knob are evenly spaced. Learn the physical positions for each quadrant to make input faster and more reliable.
- **Seed for practice**: Return to the same Seed position to practice the same sequence repeatedly. Once you can reliably complete 5+ steps at one seed, change the seed for a new challenge.
- **Fast Tempo as animation**: Setting Tempo very low (fast) makes the playback sequence a rapid visual pattern, useful as a rhythmic video overlay even without player interaction.
- **Border frames the composition**: Enable Border when mixing with input video to give the quadrant display a clean visual boundary separate from the underlying footage.
- **Score as performance metric**: The Score display shows exactly how far the player has progressed. In performance settings, it serves as a visual counter element that audiences can follow.
- **Color hue offset with video**: When overlaying Simon on colored video, sweep Quad Hue to find hue relationships that complement the source palette.
- **Bypass for reveal moments**: Keep the game running in bypass, then disable bypass at a dramatic moment to reveal the current game state as a live visual surprise.

## Glossary

| Term | Definition |
|------|------------|
| **BCD** | Binary-Coded Decimal; each decimal digit is stored in 4 bits, used for the two-digit score display. |
| **Confirm Edge** | The rising edge (Off-to-On transition) of Toggle 7, used as the player's submit action during the INPUT phase. |
| **FAIL** | Transient game state entered after an incorrect quadrant selection. Resets the game to IDLE. |
| **IDLE** | Initial game state before the first sequence begins, where the LFSR is seeded and the game prepares for playback. |
| **INPUT** | Game state where the player reproduces the sequence by selecting quadrants and confirming each choice. |
| **LFSR** | Linear Feedback Shift Register; generates the pseudo-random sequence of quadrant selections. Seeded from Knob 4. |
| **PLAYBACK** | Game state where the stored sequence is displayed to the player, flashing one quadrant at a time. |
| **Quadrant** | One of four rectangular screen regions (top-left, top-right, bottom-left, bottom-right) that serve as Simon's colored buttons. |
| **Sequence Store** | A 128-bit register holding up to 64 two-bit entries, each encoding a quadrant selection (0-3). |
| **SUCCESS** | Transient game state entered after the player correctly reproduces the entire sequence. Adds a new step and increments the score. |
| **Vsync** | Vertical synchronization pulse marking the start of a new video frame, used as the game tick clock. |
| **YUV** | A color encoding separating luminance (Y) from chrominance (U, V), used throughout the Videomancer video pipeline. |
