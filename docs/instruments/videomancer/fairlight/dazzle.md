## Overview

Every broadcast television viewer has seen the sparkle effect — a starburst of light that blooms from specular highlights, stage lights, or reflections off metallic surfaces. That effect was not accidental. It was generated by dedicated hardware that detected bright pixels in the incoming video signal and overlaid radial glint patterns on them. Dazzle is a faithful descendant of that lineage: a luminance-threshold sparkle generator.

The program chains six processing stages together — luminance threshold detection, cross or star shape kernel generation, additive intensity boost, rainbow XOR chroma overlay with hue rotation, LFSR-driven pulse modulation, and a decay accumulator for persistent sparkle trails. At conservative settings, Dazzle adds subtle highlight shimmer to a live camera feed. At extreme settings, it transforms any video into a constellation of pulsing, rainbow-colored starbursts.

The name *Dazzle* refers both to the optical sensation of being overwhelmed by bright light and to *dazzle camouflage* — the World War I naval painting technique that used bold geometric patterns to disrupt visual tracking. Here, the disruption is luminous rather than geometric: bright points in the source image explode into radial light.

## Background

### Video Sparkle Generators

The sparkle generator is a staple of broadcast video effects hardware, dating back to the 1980s. The Fairlight Computer Video Instrument (CVI) included a dedicated sparkle mode that detected bright pixels and overlaid star-shaped highlights on them, creating the glittering effect familiar from music videos, sports broadcasts, and title sequences. Unlike a simple brightness boost, the sparkle generator is *spatially selective* — it only fires at pixels above a configurable luminance threshold, leaving the rest of the image untouched. Dazzle implements this same detection-and-overlay architecture in FPGA logic.

### Thresholding and Bright Spot Detection

The foundation of any sparkle effect is luminance thresholding. Each pixel's Y (brightness) value is compared against a user-set threshold register. Pixels above the threshold are flagged as "bright" and become candidates for sparkle overlay. Pixels below the threshold pass through unmodified. The threshold control determines the sensitivity: a low threshold fires on mid-tones and highlights alike, flooding the image with sparkles; a high threshold fires only on the brightest specular peaks.

### Cross and Star Kernels

Once a bright pixel is detected, Dazzle generates a radial glint pattern centered on that pixel. In *Cross* mode, the pattern extends along the horizontal and vertical axes — a four-pointed plus sign. In *Star* mode, diagonal arms are added to create an eight-pointed starburst. The kernel is generated using scanline-based dx/dy neighbor distance checks against the Radius parameter. Larger radius values extend the arms farther from the center point; smaller values create compact, tight glints.

### Rainbow Hue Rotation

When the Rainbow toggle is engaged, Dazzle replaces the monochrome sparkle overlay with a rotating hue pattern. The implementation uses an XOR operation between the chroma channels (U and V) and the pixel's spatial coordinates (x and y counters). Because XOR is a bitwise operation on the 10-bit register values, the resulting color pattern is not a smooth gradient but a structured, interference-like rainbow that shifts across the frame. The Color knob controls the intensity of this chroma modulation.

### Fairlight Heritage

The Fairlight CVI (1984) was one of the first affordable real-time video synthesizers. Its sparkle mode became iconic in 1980s music video production — a single pass through the CVI could transform a dull studio shot into a shimmering, otherworldly scene. Dazzle inherits this concept and extends it with features the original CVI lacked: variable star shapes, persistence decay, and pulse modulation. The Pulse toggle drives the sparkle intensity through an LFSR-based speed counter, creating a flickering, breathing quality that the original CVI's static overlay could not achieve.

## Signal Flow

```
Input Video (YUV 4:4:4)
│
├── Y Channel ──────────────────────────────────────────────────
│   │
│   ├─ 1. Threshold Detection   (Y > threshold → bright flag)
│   ├─ 2. Shape Kernel          (cross or star pattern via radius)
│   ├─ 3. Pulse Modulation      (LFSR speed counter gates sparkle)
│   ├─ 4. Decay Accumulator     (persistent sparkle trails)
│   ├─ 5. Intensity Boost       (additive: Y + intensity if sparkle)
│   └─ 6. Clamp                 (saturate to 1023)
│
├── U/V Channels ───────────────────────────────────────────────
│   │
│   ├─ 1. Rainbow XOR Overlay   (U ⊕ x_counter, V ⊕ y_counter)
│   └─ 2. Color Control         (modulate chroma overlay depth)
│
├── Mix Stage ──────────────────────────────────────────────────
│   └─ interpolator_u × 3       (wet/dry crossfade per channel)
│
├── Sync Signals ───────────────────────────────────────────────
│   └─ 8-clock delay pipeline   (hsync, vsync, field passthrough)
│
└── Bypass ─────────────────────────────────────────────────────
    └─ Select original or processed signal
```

The critical interaction is between threshold detection and the shape kernel. The threshold stage produces a binary bright/not-bright flag for each pixel. That flag feeds the kernel generator, which extends the sparkle pattern outward using scanline-based distance checks. The intensity boost is additive — it adds the Intensity register value to the existing luminance rather than replacing it, so the sparkle sits on top of the original image detail. Rainbow chroma is applied only to pixels within the sparkle kernel, leaving non-sparkle pixels at their original color.

## Parameter Reference

<img src={dazzle_control_panel} alt="Videomancer front panel with Dazzle loaded"/>
*Videomancer's front panel with Dazzle active. Knobs 1–6 (top two rows of left cluster), Toggle switches 7–11 (bottom row of left cluster), Fader 12 (right side).*

### Rotary Potentiometers (Knobs 1–6)

#### Knob 1 — Threshold
| Property | Value |
|----------|-------|
| Range | 0% – 100% |
| Default | 63% |
| Suffix | % |

Sets the luminance threshold for sparkle detection. At 0%, every pixel fires the sparkle overlay — the entire image is boosted. As the threshold increases, only progressively brighter pixels trigger sparkles, until at 100% only the absolute brightest specular highlights produce glints. This is the primary sensitivity control: low values create a diffuse glow across the image; high values produce sparse, precise highlight bursts.

---

#### Knob 2 — Intensity
| Property | Value |
|----------|-------|
| Range | 0% – 100% |
| Default | 50% |
| Suffix | % |

Controls the additive luminance boost applied to pixels within the sparkle kernel. At 0%, detected bright pixels receive no additional brightness — the sparkle is invisible. As intensity increases, the sparkle overlay becomes brighter, eventually saturating the luminance channel to peak white. Because the boost is additive (Y + Intensity, clamped to 1023), the original image detail beneath the sparkle is preserved at moderate settings.

---

#### Knob 3 — Radius
| Property | Value |
|----------|-------|
| Range | 0% – 100% |
| Default | 38% |
| Suffix | % |

Determines the spatial extent of the sparkle arms. At 0%, the sparkle is a single-pixel highlight at the detected bright spot. As radius increases, the cross or star arms extend farther from the center, creating larger glint patterns. Very high radius values produce long, dramatic rays that can span a significant portion of the frame. The shape of these arms is controlled by Toggle 9 (Cross vs. Star).

---

#### Knob 4 — Decay
| Property | Value |
|----------|-------|
| Range | 0% – 100% |
| Default | 50% |
| Suffix | % |

Controls the persistence decay rate for sparkle trails. When Persistent mode (Toggle 10) is active, each sparkle's brightness decays over time rather than disappearing instantly. Low decay values cause sparkles to fade quickly; high decay values cause them to linger, creating comet-like trails as bright objects move through the frame. At 0% decay, sparkles are frame-instantaneous even with Persistent enabled.

---

#### Knob 5 — Color
| Property | Value |
|----------|-------|
| Range | 0% – 100% |
| Default | 50% |
| Suffix | % |

Modulates the depth of the rainbow chroma overlay when Rainbow (Toggle 7) is active. At 0%, the overlay is monochrome — no color shift. As the Color control increases, the XOR-based hue rotation becomes more pronounced, cycling through increasingly vivid colors across the sparkle pattern. At maximum, the sparkle arms display the full interference rainbow. Has no visible effect when Rainbow is toggled off.

---

#### Knob 6 — Speed
| Property | Value |
|----------|-------|
| Range | 0% – 100% |
| Default | 25% |
| Suffix | % |

Sets the rate of the LFSR-driven pulse modulation when Pulse (Toggle 8) is active. At 0%, the pulse rate is very slow — sparkles breathe in and out over several seconds. As speed increases, the pulsation becomes more rapid, creating a flickering, strobe-like sparkle effect. At maximum, the modulation is fast enough to appear as a shimmer rather than a distinct pulse. Has no visible effect when Pulse is toggled off.

---

### Toggle Switches (Switches 7–11)

| Switch | Off | On |
|--------|-----|-----|
| **7 — Rainbow** | Off | On |
| **8 — Pulse** | Off | On |
| **9 — Star Shape** | Cross | Star |
| **10 — Persistent** | Off | On |
| **11 — Bypass** | Off | On |

Toggles 7–11 control five independent binary options. Rainbow (7) and Pulse (8) enable optional modulation modes that add visual complexity. Star Shape (9) selects between two kernel geometries. Persistent (10) enables the decay accumulator for sparkle trails. Bypass (11) routes the unprocessed signal to the output.

---

### Linear Potentiometer (Fader 12)

#### Fader 12 — Mix
| Property | Value |
|----------|-------|
| Range | 0% – 100% |
| Default | 100% |
| Suffix | % |

Wet/dry crossfade between the original (dry) signal and the sparkle-processed (wet) signal. At 0%, the output is the unprocessed source. At 100%, the output is the fully processed sparkle overlay. Intermediate values blend the two, allowing subtle sparkle enhancement to be mixed into the source at any desired strength.

## Guided Exercises

These exercises progress from basic highlight detection to full sparkle animation with rainbow chroma and persistence trails.

### Exercise 1: Threshold Highlight Detection

<img src={dazzle_exercise1_result} alt="Threshold Highlight Detection result"/>
*Threshold Highlight Detection — simulated result across source images.*
**Source**: A live camera feed or recorded footage with visible specular highlights — metallic objects, glass reflections, or stage lighting.

**Objective**: Learn how the threshold and intensity controls interact to create basic luminance-driven highlight bursts.

1. **Set threshold high**: Turn Threshold to about 80%. Only the brightest highlights should trigger sparkles.
2. **Add intensity**: Increase Intensity to about 50%. Bright spots bloom into white highlights.
3. **Sweep threshold down**: Slowly lower Threshold toward 30%. Watch as progressively dimmer pixels trigger the sparkle overlay.
4. **Adjust radius**: Increase Radius to about 40%. The sparkle points grow into visible cross-shaped glints.
5. **Compare**: Toggle Bypass (Switch 11) to see the difference between raw and processed signal.

**Key concepts**: Luminance thresholding selects which pixels receive sparkle overlay, intensity controls the additive brightness boost, radius extends the sparkle arms outward from the detection point

---

### Exercise 2: Rainbow Starbursts

<img src={dazzle_exercise2_result} alt="Rainbow Starbursts result"/>
*Rainbow Starbursts — simulated result across source images.*
**Source**: High-contrast footage with scattered bright points — city lights at night, candle flames, or sequined fabric.

**Objective**: Explore rainbow chroma overlay and star kernel geometry.

1. **Base sparkle**: Set Threshold ~60%, Intensity ~60%, Radius ~50%.
2. **Enable rainbow**: Toggle Rainbow (Switch 7) on. Sparkle points gain a colorful XOR pattern.
3. **Increase color**: Sweep Color from 0% to 80%. The rainbow hues become more vivid and saturated.
4. **Switch to star**: Toggle Star Shape (Switch 9) to Star. The four-pointed cross becomes an eight-pointed starburst.
5. **Increase radius**: Push Radius to ~70%. The star arms extend dramatically across the frame.
6. **Mix subtlety**: Lower Mix to ~60% to blend the starbursts gently into the source image.

**Key concepts**: Rainbow mode applies XOR-based chroma modulation creating structured interference patterns, star kernels add diagonal arms to the cross pattern, mix fader allows partial blending

---

### Exercise 3: Pulsing Persistent Trails

<img src={dazzle_exercise3_result} alt="Pulsing Persistent Trails result"/>
*Pulsing Persistent Trails — simulated result across source images.*
**Source**: Slowly moving footage with bright highlights — a hand-held flashlight, a rotating disco ball, or a sparkler.

**Objective**: Combine pulse modulation and persistence decay to create animated sparkle trails.

1. **Base sparkle**: Set Threshold ~50%, Intensity ~70%, Radius ~40%.
2. **Enable persistence**: Toggle Persistent (Switch 10) on. Sparkles linger after the bright source moves away.
3. **Set decay**: Increase Decay to ~60%. Sparkle trails fade slowly, creating comet-like afterimages.
4. **Enable pulse**: Toggle Pulse (Switch 8) on. The sparkle intensity begins to breathe rhythmically.
5. **Adjust speed**: Sweep Speed from ~20% to ~60%. Find a pulsation rate that complements the motion in the source.
6. **Add rainbow**: Toggle Rainbow on and set Color ~40% for subtle hue shifts in the trails.
7. **Sculpt mix**: Adjust Mix to ~80% to let the original image show through the sparkle field.

**Key concepts**: Persistent mode accumulates sparkle brightness with configurable decay, pulse modulation creates rhythmic intensity variation via LFSR counter, combining persistence and pulse creates animated glitter fields

## Tips

- **Threshold is sensitivity**: Low threshold = many sparkles (floods the image). High threshold = few sparkles (only the hottest highlights). Start high and lower gradually until you get the desired density.
- **Intensity saturates**: The boost is additive and clamped to peak white (1023). High intensity on a high-luminance source will clip — the sparkle becomes a flat white patch. Use moderate intensity to preserve the shape of the glint arms.
- **Radius and star interact**: Star mode with high radius creates dramatic eight-pointed rays that can dominate the frame. Cross mode with moderate radius is more subtle and broadcast-friendly.
- **Rainbow needs sparkle pixels**: The Rainbow toggle only colors pixels within the sparkle kernel. If Threshold is set too high and no pixels trigger, Rainbow has no visible effect.
- **Persistence builds up**: With Persistent on and high Decay, static highlights accumulate to peak white over several frames. Use for deliberate bloom effects or lower Decay for balanced trails.
- **Feedback loops**: Routing the Dazzle output back to the input creates recursive sparkle — each frame's sparkles become triggers for the next frame's threshold detection, producing cascading highlight explosions.
- **Pulse adds life**: Even subtle pulse modulation (Speed ~20%) adds organic flicker to what would otherwise be a static overlay. Combine with Persistent for breathing, living sparkle fields.
- **Mix for subtlety**: Use Mix at 30–50% to add a gentle sparkle sheen to live camera footage without overwhelming the source material.

## Glossary

| Term | Definition |
|------|------------|
| **Additive Overlay** | A compositing operation that adds the sparkle brightness to the existing pixel value, preserving underlying detail until clipping occurs. |
| **Chroma** | The color information in a video signal, encoded as U and V components in YUV color space. |
| **Cross Kernel** | A four-pointed sparkle shape extending along the horizontal and vertical axes from a center pixel. |
| **Decay** | The rate at which accumulated sparkle brightness fades over successive frames when persistence is active. |
| **FPGA** | Field-Programmable Gate Array; the reconfigurable hardware chip that implements Videomancer's real-time video processing. |
| **Hue Rotation** | Shifting the color angle of a pixel around the color wheel; here implemented via XOR with spatial coordinates. |
| **LFSR** | Linear-Feedback Shift Register; a shift register whose input bit is a function of its previous state, producing pseudo-random sequences. |
| **Luma** | The brightness component (Y) of a YUV video signal, representing perceived luminance. |
| **Pipeline** | A chain of processing stages where each stage performs one operation per clock cycle on streaming pixel data. |
| **Specular Highlight** | A bright reflection from a shiny surface — the primary target for sparkle detection. |
| **Star Kernel** | An eight-pointed sparkle shape adding diagonal arms to the cross kernel pattern. |
| **Threshold** | A luminance cutoff value; pixels above the threshold are flagged as bright and receive sparkle overlay. |
| **XOR** | Exclusive OR; a bitwise logic operation that flips bits where the two operands differ, producing structured interference patterns. |
| **YUV** | A color encoding that separates luminance (Y) from chrominance (U, V); the native format of Videomancer's 30-bit video pipeline. |
